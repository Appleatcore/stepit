STEPIT / HEIGHTMAP / RADAR

StepIt 中“雷达高程图插件”的实际设计方法

这份文档基于当前仓库源码梳理 StepIt 高程图模块的真实结构。核心结论先说在前面： StepIt 本身不负责把雷达点云直接建成高程图； 它做的是订阅外部已经生成好的 GridMap 高程图， 再结合机器人位姿或 TF 中的 radar 坐标系， 从地图中采样出固定布局的高度数组，送入策略网络的 heightmap 输入。

1. 职责边界

如果你现在理解成“StepIt 插件从毫米波雷达原始数据直接生成 elevation map”，这个理解是不准确的。

在当前仓库中，高程图链条分成两层：

  1. 外部地图模块负责把雷达/传感器数据融合成 grid_map_msgs/msg/GridMap。
  2. StepIt 的 heightmap_subscriber / heightmap_subscriber2 负责订阅地图、采样、整理成策略输入。

也就是说，radar 在 StepIt 侧主要扮演的是采样参考坐标系，不是点云建图器。

3. 总体数据流

上游传感器系统：雷达/其他感知源生成 /elevation_map，消息类型是 grid_map_msgs/msg/GridMap。
StepIt ROS2 插件：heightmap_subscriber2 订阅该地图。
位姿来源：通过 robot_frame_id: "radar" 从 TF 查询雷达位姿，或者从 /odometry、PoseStamped 这类定位话题订阅。
局部采样：在机器人附近的固定采样网格上读取 elevation 和 uncertainty。
结果整理：得到固定长度的 heightmap 向量，例如你的 Go2W 配置里是 187 维。
送入策略：网络输入定义见 actor.yml，高程图会和本体观测、速度命令、上一时刻动作拼接。

4. 基类设计：先定义采样网格

真正的 ROS2 订阅器不是从零写起，而是继承基础类 DummyHeightmapSource。

源码：plugin/policy_neuro/src/heightmap_source.cpp

这个基类先解决两件事：

  1. 定义采样点布局：可以用 dimension + grid_size + x_major 自动生成规则网格，也可以显式给 sample_coords。
  2. 注册输出字段：heightmap 和 heightmap_uncertainty。
dimension: [17, 11]
grid_size: [0.1, 0.1]
x_major: false

这表示采样窗口宽度是 17 x 11 个采样点，每格 0.1m，总共 187 个采样值。

5. ROS2 插件做了什么

源码：plugin/policy_neuro_ros2/src/heightmap_subscriber2.cpp

  1. 读取 heightmap.yml 里的地图话题、定位方式、插值方式、超时阈值。
  2. 订阅 GridMap。
  3. 如果配置了 robot_frame_id，则通过 TF 查询这个坐标系在地图坐标系中的位姿。
  4. 否则订阅显式定位话题，如 /odometry。
  5. 每个控制周期根据位姿把局部采样网格旋转、平移到全局地图中，再逐点采样。
  6. 必要时把采样点再发布成调试点云 heightmap_samples。

6. “radar” 在这里到底是什么意思

在你当前的策略配置里，localization_subscriber.robot_frame_id: "radar" 的含义是： 从 TF 中查找 radar 坐标系在地图坐标系下的位置和朝向，并以它为中心做高程采样。

这带来的直接效果是：

  • 采样中心不是机器人 base，而是雷达安装坐标系。
  • 如果雷达的安装位姿与机体中心有偏移，采样网格就会跟着偏移。
  • 如果 radar 朝向与底盘朝向不同，采样网格也会按 radar 朝向旋转。

因此，radar 更准确的说法应是“采样参考帧”，而不是“雷达建图插件”。

7. 运行期判定逻辑

插件不会盲目输出数据，而是先做就绪检查：

  1. 订阅器是否启用。
  2. 是否收到了高程图。
  3. TF 或定位消息是否可用。
  4. 高程图和定位是否超时。
  5. 地图中是否存在 elevation 层和配置的 uncertainty 层。

如果检查失败，插件不会报错退出策略，而是回退成安全输出：

elevation_.setZero();
uncertainty_.setConstant(max_uncertainty_);

也就是输出零高程图和最大不确定度。

8. 采样算法细节

每个控制周期，采样逻辑是：

  1. 取雷达/定位位姿的二维位置 (x, y) 和偏航角。
  2. 将局部采样网格中的每个 local_coord 旋转到全局。
  3. 用 grid_map::atPosition() 从高程图指定 layer 插值得到高度。
  4. 再从 uncertainty layer 读取不确定度。
  5. 采样越界或非有限值时，记为 NaN，后续回填。

代码中的局部到全局变换可以概括成：

global_coord = robot_pos + yaw_rotation * local_coord

9. NaN、均值与不确定度处理

场景 处理方式
高度采样越界或异常 先写成 NaN，后续用当前采样窗口内的均值回填。
高度 NaN 回填后 对应不确定度使用 max_uncertainty 语义保守处理。
elevation_zero_mean: true 将所有采样点减去均值，只保留相对起伏。
uncertainty_layer == variance 先开方，再乘 uncertainty_scaling。
没有 uncertainty layer 直接使用 default_uncertainty。

你当前的 Go2W 配置里用的是：

elevation_zero_mean: false
uncertainty_layer: "uncertainty"
uncertainty_squared: false
uncertainty_scaling: 0.25

这意味着你保留了绝对高程趋势，而不是只保留相对高度起伏。

10. 调试发布器

如果开启 height_sample_publisher，插件会把采样点重新发布成 PointCloud2：

  • x, y, z：采样点全局位置和采样后的高度。
  • rgb：用红绿颜色编码不确定度，越红表示不确定度越高。

这非常适合拿 RViz 直接看“策略到底看到了哪里”。

11. 为什么策略会自动拿到高程图

在 StepIt 的神经策略里，模块和字段源是自动解析的。

源码：plugin/policy_neuro/src/neuro_policy.cpp

只要网络输入要求 heightmap，StepIt 就会去找哪个模块能提供它：

  • dummy_heightmap_source 是低优先级兜底实现。
  • heightmap_subscriber / heightmap_subscriber2 是高优先级真实实现。

所以在 ROS2 插件正常加载时，如果你的策略需要 heightmap，通常会优先用真实订阅器。

12. 你当前 Go2W 配置的实际含义

以当前策略目录 policy/go2w_policy_cusrl_with_sensor_normal/ 为例：

文件 作用
heightmap.yml 定义采样窗口为 17 x 11 = 187，订阅 /elevation_map，使用 radar 作为 TF 参考帧。
actor.yml 要求网络输入包含 heightmap: 187，与本体观测拼接成总观测。
field_ops.yml 在送入网络前，对高程图做 scale: -1.0 和 bias: -0.15 的语义变换。
policy.yml 模块显式写了 cmd_vel_source、field_ops、actor；而 heightmap 会在依赖解析阶段自动补齐。

13. 典型使用方法

13.1 构建依赖

ROS2 插件需要这些依赖：

sudo apt install ros-${ROS_DISTRO}-cv-bridge ros-${ROS_DISTRO}-grid-map-ros

源码里还显式依赖：

geometry_msgs
grid_map_msgs
grid_map_ros
nav_msgs
sensor_msgs
std_msgs
tf2_ros

13.2 准备上游话题

  1. 准备一个发布 grid_map_msgs/msg/GridMap 的节点，话题名通常是 /elevation_map。
  2. 确保地图里至少有 elevation 层。
  3. 如果你启用了不确定度，还要有 uncertainty 或 variance 层。

13.3 准备定位或 TF

  1. 推荐方式：发布 TF，使地图坐标系下可以查到 radar。
  2. 备用方式：在 localization_subscriber 中配置 /odometry 等定位话题。

13.4 准备策略配置

dimension: [17, 11]
grid_size: [0.1, 0.1]
x_major: false

grid_map_subscriber:
  topic: "/elevation_map"
  default_enabled: true

localization_subscriber:
  robot_frame_id: "radar"

13.5 保证网络输入匹配

input_fields:
  observation:
  - { name: ang_vel, size: 3 }
  - { name: gravity, size: 3 }
  - { name: cmd_vel, size: 3 }
  - { name: joint_pos, size: 16 }
  - { name: joint_vel, size: 16 }
  - { name: last_action, size: 16 }
  - { name: heightmap, size: 187 }

14. 常见误区

误区 1：把 radar 理解成“雷达原始数据入口”。
实际上它只是 TF 参考帧。
误区 2：以为 StepIt 会自动做 elevation mapping。
实际上 StepIt 只消费地图，不负责地图生成。
误区 3：只改了 heightmap.yml，没改网络输入维度。
采样点总数必须和网络要求一致。

15. 常见排查点

  1. 插件没加载：通常是 ROS2 依赖没装全，特别是 grid_map_msgs、grid_map_ros、tf2_ros。
  2. 看不到高程图：检查 /elevation_map 是否真在发 GridMap。
  3. 输出一直是零：通常是订阅器未启用、地图没到、TF 断了，或者超时后回退到 dummy 行为。
  4. 方向错位：优先检查 robot_frame_id 是否应该是 radar 还是 base_link。
  5. 网络效果差：确认 x_major、elevation_zero_mean、field_ops.yml 中的 heightmap 仿射变换与训练保持一致。

16. 结论

如果用一句话概括当前 StepIt 的设计：

StepIt 的“高程图插件”是一个高程图订阅与局部采样插件，不是雷达建图插件。

对你现在这套 Go2W 配置来说，正确理解应该是：

  1. 外部系统先把雷达感知结果融合成 /elevation_map。
  2. StepIt 用 radar 坐标系在这张地图上采样出 187 维局部高度向量。
  3. 再经过 field_ops.yml 的固定语义变换后，送入策略网络。
